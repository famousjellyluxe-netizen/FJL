KEY FINDINGS:

1. CRITICAL - Order Access Control Vulnerability
   Location: src/routes/orders.js lines 45, 58
   Issue: GET /orders/:id and GET /orders/number/:orderNumber are PUBLIC endpoints
   Risk: Any user can retrieve ANY order by guessing order number or ID, exposing customer data
   Fix: Add JWT authentication and verify customer ownership

2. CRITICAL - Route Ordering Problem in Customers Routes
   Location: src/routes/customers.js
   Issue: Specific routes (like /members/subscribe) come AFTER parameterized routes (/:id)
   Risk: POST /members/subscribe might match /:id route pattern, causing request failures
   Fix: Reorder routes - specific routes BEFORE parameterized routes

3. CRITICAL - Missing Permission Definition
   Location: src/routes/settings.js line 25
   Issue: requirePermission('manage_settings') used but permission NOT defined in auth.js
   Risk: Settings endpoint will always return 403 Forbidden for all roles
   Fix: Add manage_settings to owner/manager role permissions in auth.js

4. CRITICAL - Schema Column Mismatch
   Location: Code references order.stock_deducted but NOT in SUPABASE_SCHEMA.sql
   Issue: Migration add_stock_deducted_to_orders.sql must be applied
   Risk: Order status changes will fail

5. CRITICAL - Newsletter Unsubscribe Token Missing from Schema
   Location: Code references unsubscribe_token but NOT in SUPABASE_SCHEMA.sql
   Issue: Migration add_unsubscribe_token.sql must be applied
   Risk: Newsletter unsubscribe functionality will fail

6. HIGH - Stock Management Race Condition
   Location: src/routes/orders.js and src/services/orderService.js
   Issue: Stock validated BEFORE order creation but reduction happens AFTER payment
   Scenario: Two concurrent orders might both pass stock check, causing negative inventory
   Fix: Use database locks or atomic transactions

7. HIGH - Public Product Variants Endpoint
   Location: src/routes/products.js line 143
   Issue: GET /products/:id/variants is PUBLIC, exposing real-time inventory levels
   Risk: Competitors can scrape stock data
   Fix: Add verifyJWT, requireAdmin middleware

8. MEDIUM - Missing Input Validations
   - Categories DELETE: reassign_to parameter not validated as UUID
   - Settings PUT: No validation chains defined
   - Products GET: category filter not validated as UUID

9. MEDIUM - JWT Secret in Source Code
   Location: src/config/jwt.js line 14
   Issue: Development secret hardcoded and visible in git
   Risk: If used in production, secret is compromised
   Fix: Remove default; require explicit JWT_SECRET

10. MEDIUM - Weak Order Number Generation
    Location: src/services/orderService.js lines 7-10
    Issue: Random number not cryptographically secure, collision risk
    Fix: Use UUID suffix instead of random substring

CRITICAL BUSINESS LOGIC ISSUES:

1. Stock Race Condition:
   - Order creation validates stock at time T1
   - Multiple orders can pass validation
   - Stock reduction happens at T2 (after payment)
   - Race window allows overbooking

2. Payment Failure Handling:
   - Inconsistent import statements (default vs named imports)
   - May fail to restore stock if imports don't match
   - Uses productService.default in one place, import * in another

3. Category Slug Collisions:
   - Auto-generation doesn't check for duplicates
   - Two "Red Shirts" could create duplicate "red-shirts" slugs
